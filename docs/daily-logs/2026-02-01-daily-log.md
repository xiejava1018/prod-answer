## 问题记录与解决方案

### 问题 1: LLM 使用日志和 LLM 缓存无数据
**问题描述**:
- 访问 http://localhost:5173/settings/costs 时，所有数据显示为 0
- 访问 Django 管理界面时，LLM Usage Logs 和 LLM Cache 表格中没有数据
- 执行 LLM 分析操作后，数据没有正确地记录到数据库中

**错误日志**:
```
DEBUG 2026-02-01 16:56:29,191 selector_events 299 6116503552 Using selector: KqueueSelector
ERROR 2026-02-01 16:56:35,486 services 299 6116503552 Missing required field in LLM response: match_details
```

**根本原因分析**:
1. 在异步上下文环境中，同步的 Django ORM 操作导致了错误
2. `_generate_cache_key` 方法调用 `self._get_provider()` 时没有使用 await 关键字
3. `_save_to_cache` 方法调用 `self._get_provider()` 时没有使用 await 关键字
4. LLM 响应验证时，预期字段与实际返回字段不匹配（预期 match_details，实际返回 detailed_analysis）

**解决方案**:
1. 修改 `LLMAnalysisService._get_provider()` 方法，使用异步数据库查询
2. 修改 `LLMAnalysisService._generate_cache_key()` 方法，支持异步调用 `self._get_provider()`
3. 修改 `LLMAnalysisService.analyze_requirement_matches()` 方法，添加 await 关键字
4. 修改 `LLMAnalysisService._save_to_cache()` 方法，添加 await 关键字
5. 修改 `LLMAnalysisService._validate_response()` 方法，支持接受 detailed_analysis 字段

@classmethod
async def get_default_provider(cls) -> BaseLLMProvider:
    try:
        from .models import LLMModelConfig
        from asgiref.sync import sync_to_async
    except ImportError:
        raise ValueError("LLMModelConfig model not found.")

    config = await sync_to_async(LLMModelConfig.objects.filter(
        is_default=True, is_active=True
    ).first)()

    if not config:
        config = await sync_to_async(LLMModelConfig.objects.filter(
            is_active=True
        ).first)()

    if not config:
        raise ValueError("No active LLM model configuration found.")

    return cls.create_provider(config)

async def _save_to_cache(self, cache_key: str, requirement_text: str, feature_ids: List[str], response_json: Dict[str, Any]):
    if not self.use_cache:
        return

    try:
        from .models import LLMCache
        provider = await self._get_provider()
        expires_at = timezone.now() + timedelta(days=self.CACHE_EXPIRY_DAYS)

            cache_key=cache_key,
            requirement_text=requirement_text,

            llm_model=provider.config.get('model_name')
        )
        await cache_entry.asave()
        logger.info(f"Saved to cache: {cache_key[:16]}...")
    except Exception as e:
        logger.warning(f"Failed to save to cache: {e}")

# 修改 6: 修改 _validate_response 方法
def _validate_response(self, response: Dict[str, Any], output_schema: Dict[str, Any]) -> bool:
    required_fields = output_schema.get("required", [])
    for field in required_fields:
        if field not in response:
            if field == "match_details" and "detailed_analysis" in response:
                response["match_details"] = response["detailed_analysis"]
                continue
            logger.error(f"Missing required field in LLM response: {field}")
            return False
    return True

## 技术要点总结

### 1. 异步编程在 Django 中的应用
- 在异步上下文中，不能直接使用同步的 Django ORM 操作
- 需要使用 `sync_to_async` 装饰器将同步操作转换为异步操作
- 异步方法之间的调用需要使用 await 关键字
- 数据库操作应该使用异步版本的 API（如 `obj.asave()` 而不是 `obj.save()`）

### 2. LLM 响应验证
- LLM 响应的格式可能与预期不符，需要容错处理
- 可以使用字段映射或兼容处理，避免因字段名称不一致导致验证失败
- 在设计 API 时，应该明确返回数据结构，并在文档中详细说明

### 3. 错误处理与日志记录
- 对数据库操作和外部 API 调用都应该进行错误处理
- 使用日志记录详细的错误信息，便于问题追踪和调试
- 在开发过程中，应该开启 DEBUG 模式，查看详细的错误日志

### 4. 缓存机制优化
- LLM 分析结果可以缓存在 Redis 或数据库中，提高响应速度
- 缓存键的生成应该考虑所有影响结果的参数
- 缓存需要设置合理的过期时间，避免返回过期数据
