# 产品门户规划方案

**创建日期**: 2026-01-31
**版本**: v1.0
**状态**: 规划中

---

## 一、项目背景

基于现有"产品能力匹配系统"，规划面向最终用户的产品门户，将内部管理工具升级为对外服务门户。

**现有系统功能**:
- 产品功能特性管理
- 需求文件解析（Excel/CSV/Word）
- AI语义匹配（基于Embedding向量）
- 匹配结果可视化

**门户目标**: 提供直观的产品展示和智能匹配服务，降低使用门槛，提升用户体验。

---

## 二、门户定位与目标用户

### 2.1 门户定位
产品能力展示与智能匹配门户，帮助用户快速找到满足需求的产品解决方案。

### 2.2 目标用户
- **外部客户**: 寻找产品解决方案
- **内部销售**: 快速匹配客户需求
- **产品管理者**: 查看产品能力覆盖度

## 4.1 门户首页 (Portal Home)

### 功能点

#### 1. Hero区域
- **醒目标题和简介**: "智能匹配产品门户 - 基于AI语义分析，快速找到满足需求的产品"
- **快速需求输入框**: 支持文本输入和文件上传
- **立即匹配按钮**: 一键触发匹配流程

#### 2. 热门产品推荐
- **推荐算法**: 基于历史匹配次数、产品热度
- **展示形式**: 产品卡片网格布局
- **卡片内容**: 产品名称、简介、匹配度、标签

#### 3. 产品分类导航
- **分类维度**: 产品类别、子系统类型、应用场景
- **交互方式**: 图标+名称的网格布局，点击跳转
- **数据驱动**: 动态读取产品分类数据

#### 4. 使用指南
- **三步快速上手**: 配置模型 → 录入产品 → 上传需求 → 执行匹配
- **功能亮点展示**: AI语义匹配、多格式支持、可视化结果

## 4.3 智能匹配中心 (Matching Center)

### 4.3.1 需求输入页

#### 功能点

**1. 文本输入**
- 多行文本输入框
- 支持批量输入（每行一个需求）
- 实时字数统计
- 需求模板加载

**2. 文件上传**
- 支持Excel (.xlsx, .xls)
- 支持CSV (.csv)
- 支持Word (.docx)
- 拖拽上传区域
- 文件大小限制（10MB）
- 文件类型验证

**3. 需求模板**
- 内置模板下载
  - 标准需求模板（Excel）
  - 功能清单模板（CSV）
  - 技术规格模板（Word）

**4. 示例需求**
- 加载示例数据
- 帮助用户理解输入格式
- 快速体验匹配功能

**5. 高级选项**
- 匹配阈值设置（0.75-0.95）
- 选择Embedding模型
- 匹配范围选择（全部产品/指定类别）

#### 交互流程

```
用户进入需求输入页
    ↓
选择输入方式（文本/文件）
    ↓
输入需求或上传文件
    ↓
配置高级选项（可选）
    ↓
点击"开始匹配"按钮
    ↓
跳转到匹配结果页
```

### 4.3.2 匹配结果页

#### 功能点

**1. 匹配结果可视化**
- **饼图**: 满足项/部分满足项/不满足项占比
- **柱状图**: 各产品匹配度对比
- **雷达图**: 多维度能力覆盖评估

**2. 产品匹配度排序列表**
- 按匹配度降序排列
- 显示匹配度百分比
- 显示满足项/部分满足项/不满足项数量

**3. 分类展示**
- **满足项** (≥0.85): 绿色标签，显示匹配的功能特性
- **部分满足项** (0.75-0.85): 黄色标签，显示相似功能
- **不满足项** (<0.75): 红色标签，显示缺失能力

**4. 详细匹配报告**
- 每个需求的匹配详情
- 相似功能推荐
- 替代方案建议

**5. 报告导出**
- **PDF导出**: 完整匹配报告，包含图表和详细数据
- **Excel导出**: 结构化数据，便于进一步分析
- **分享链接**: 生成临时链接，方便分享结果

```typescript
export const usePortalStore = defineStore('portal', () => {
  // 热门产品

// store/modules/productCatalog.ts
export const useProductCatalogStore = defineStore('productCatalog', () => {
  // 产品列表
  const products = ref<Product[]>([])
  
  // 筛选条件
  const filters = ref({
    category: '',
    subsystem: '',
    search: ''
  })
  
  // 加载产品列表
  async function loadProducts() {
    const res = await productApi.getProducts(filters.value)
    products.value = res.data
  }
  
  return {
    products,
    filters,
    loadProducts
  }
})
```

```python
class ProductListView(APIView):
    """产品列表（支持搜索筛选）"""
    
    def get(self, request):
        # 获取筛选参数
        search = request.GET.get('search', '')
        category = request.GET.get('category', '')
        subsystem = request.GET.get('subsystem', '')
        
        # 构建查询条件
        queryset = Product.objects.all()
        if search:
            queryset = queryset.filter(
                Q(name__icontains=search) |
                Q(description__icontains=search)
            )
        if category:
            queryset = queryset.filter(category=category)
        if subsystem:
            queryset = queryset.filter(subsystem_type=subsystem)
        
        # 序列化返回
        serializer = ProductSerializer(queryset, many=True)
        return Response(serializer.data)
```

```python
# portal/views/matching.py
class MatchingInputView(APIView):
    """需求输入和匹配"""
    
    def post(self, request):
        # 获取输入数据
        requirement_text = request.data.get('requirement_text', '')
        requirement_file = request.FILES.get('requirement_file')
        threshold = request.data.get('threshold', 0.75)
        
        # 处理文件上传
        if requirement_file:
            requirement_text = self.parse_file(requirement_file)
        
        # 创建需求记录
        requirement = Requirement.objects.create(
            requirement_text=requirement_text,
            requirement_type='text'
        )
        
        # 执行匹配
        matcher = ProductMatcher()
        results = matcher.match(
            requirement_text=requirement_text,
            threshold=threshold
        )
        
        # 保存匹配结果
        matching_result = MatchingResult.objects.create(
            requirement=requirement,
            results=results
        )
        
        return Response({
            'requirement_id': requirement.id,
            'matching_result_id': matching_result.id,
            'results': results
        })

class MatchingResultView(APIView):
    """匹配结果详情"""
    
    def get(self, request, pk):
        matching_result = get_object_or_404(MatchingResult, pk=pk)
        serializer = MatchingResultSerializer(matching_result)
        return Response(serializer.data)

class MatchingHistoryView(APIView):
    """匹配历史"""
    
    def get(self, request):
        # 获取用户历史记录
        user = request.user
        history = MatchingResult.objects.filter(
            requirement__created_by=user
        ).order_by('-created_at')
        
        serializer = MatchingHistorySerializer(history, many=True)
        return Response(serializer.data)
```

```python
# portal/cache.py
from django.core.cache import cache
import json

class PortalCache:
    """门户缓存管理"""
    
    @staticmethod
    def get_hot_products():
        """获取热门产品（缓存）"""
        key = 'portal:hot_products'
        products = cache.get(key)
        
        if not products:
            # 从数据库获取
            products = Product.objects.filter(is_active=True)[:10]
            cache.set(key, products, 3600)  # 缓存1小时
        
        return products
    
    @staticmethod
    def invalidate_hot_products():
        """清除热门产品缓存"""
        cache.delete('portal:hot_products')
    
    @staticmethod
    def get_matching_result(result_id):
        """获取匹配结果（缓存）"""
        key = f'portal:matching_result:{result_id}'
        result = cache.get(key)
        
        if not result:
            # 从数据库获取
            result = MatchingResult.objects.get(id=result_id)
            cache.set(key, result, 1800)  # 缓存30分钟
        
        return result
```

## 九、风险评估与应对

## 9.1 技术风险

### 9.1.1 Embedding模型响应慢

**风险描述**:
- OpenAI API响应时间长（>5秒）
- 影响用户体验
- 可能导致请求超时

**影响程度**: 高

**应对措施**:
1. **异步处理**
   - 使用Celery异步执行匹配任务
   - 前端轮询或WebSocket推送结果
   - 显示任务进度

2. **缓存策略**
   - 缓存相同需求的匹配结果
   - 设置合理缓存时间（1小时）
   - 缓存热门产品Embedding

3. **降级方案**
   - 使用本地Sentence-Transformers模型
   - 响应时间控制在2秒内
   - 精度略有下降但可接受

4. **性能监控**
   - 监控API响应时间
   - 设置告警阈值（>3秒）
   - 自动切换备用方案

### 9.1.2 产品数据量大加载慢

**风险描述**:
- 产品数量超过1000个
- 列表页加载缓慢
- 搜索响应时间长

**影响程度**: 中

**应对措施**:
1. **分页加载**
   - 默认每页20条
   - 支持无限滚动
   - 虚拟滚动优化

2. **索引优化**
   - 创建PostgreSQL全文搜索索引
   - 使用pgvector向量索引
   - 优化查询语句

3. **缓存策略**
   - 缓存热门产品数据
   - 缓存搜索结果
   - 缓存产品详情

4. **数据库分片**
   - 按产品类别分表
   - 按时间范围分区
   - 读写分离

### 9.1.3 用户上传恶意文件

**风险描述**:
- 上传恶意脚本文件
- 上传超大文件导致服务崩溃
- 上传病毒文件

**影响程度**: 中

**应对措施**:
1. **文件类型限制**
   - 白名单机制（.xlsx, .csv, .docx）
   - MIME类型验证
   - 文件头签名验证

2. **文件大小限制**
   - 最大10MB
   - 前端验证
   - 后端二次验证

3. **病毒扫描**
   - 集成ClamAV病毒扫描
   - 隔离可疑文件
   - 定期清理临时文件

4. **沙箱处理**
   - 在隔离环境解析文件
   - 限制文件操作权限
   - 监控异常行为

### 9.1.4 匹配准确度不高

**风险描述**:
- 匹配结果与用户期望不符
- 阈值设置不合理
- 语义理解偏差

**影响程度**: 高

**应对措施**:
1. **阈值调优**
   - 提供阈值调整界面
   - 支持用户自定义阈值
   - 记录最佳阈值配置

2. **模型优化**
   - 收集用户反馈
   - 定期重新训练模型
   - 使用领域特定语料

3. **人工干预**
   - 支持人工标注
   - 建立反馈机制
   - 持续优化算法

4. **多模型融合**
   - 使用多个Embedding模型
   - 结果加权融合
   - 提高鲁棒性

## 9.2 业务风险

### 9.2.1 用户接受度低

**风险描述**:
- 用户习惯原有流程
- 不愿意尝试新系统
- 学习成本顾虑

**影响程度**: 中

**应对措施**:
1. **用户培训**
   - 制作操作视频
   - 编写使用手册
   - 组织培训会议

2. **渐进式迁移**
   - 保留原有系统
   - 并行运行一段时间
   - 逐步引导用户迁移

3. **用户体验优化**
   - 简化操作流程
   - 提供操作引导
   - 优化界面设计

4. **激励机制**
   - 设立奖励机制
   - 收集用户反馈
   - 快速响应问题

### 9.2.2 数据安全风险

**风险描述**:
- 敏感产品信息泄露
- 用户数据泄露
- 未授权访问

**影响程度**: 高

**应对措施**:
1. **权限控制**
   - 基于角色的访问控制（RBAC）
   - 细粒度权限管理
   - 操作日志记录

2. **数据加密**
   - 传输层HTTPS加密
   - 敏感数据加密存储
   - API密钥加密

3. **安全审计**
   - 定期安全扫描
   - 漏洞修复
   - 渗透测试

4. **合规性**
   - 符合GDPR等法规
   - 数据保护协议
   - 隐私政策

### 9.2.3 系统稳定性风险

**风险描述**:
- 高并发访问导致系统崩溃
- 第三方服务不可用
- 数据库连接耗尽

**影响程度**: 高

**应对措施**:
1. **负载均衡**
   - 使用Nginx负载均衡
   - 多实例部署
   - 自动扩容

2. **熔断降级**
   - 第三方服务熔断
   - 核心功能降级
   - 优雅降级提示

3. **监控告警**
   - 系统监控（Prometheus）
   - 日志收集（ELK）
   - 告警通知（钉钉/邮件）

4. **容灾备份**
   - 数据库主从复制
   - 定期备份
   - 灾难恢复演练
